# Contract de decizie pentru etapa 0: colecții simple și pachete Scene2D

> Data: 2026-09-24
> Status: **decizii selectate sub autoritatea delegată de utilizator; auditul artefactelor etapei 0 acceptat, checkpoint-ul checklist în re-audit**
> Ledger sursă: [planul Scene2D](2026-09-23-scene2d-simple-collections-and-internal-spatial.md), cu etapa 0 bifată după acceptarea artefactelor, etapa 1 încă neîncepută.
> Scopul acestui document: un contract verificabil și inventarul limitelor, nu un al doilea plan de implementare.

## 1. Ce este decis și ce nu

**Decizii anterioare ale utilizatorului:** `SceneItems2D` va accepta `IEnumerable` și colecții observabile; Tetris va folosi `ObservableCollection<TetrisSpriteModel>` fără catalog/loader spațial manual; familia publică de sursă/intrare/lease/rezidență spațială va dispărea fără alias sau cale publică avansată echivalentă. `Scene2D.Children`, `Sprite2D` direct și `TileMap2D.FromModel` rămân. Aplicația trebuie să poată încărca hărți și obiecte din fișiere proprii sau de pe server printr-un contract public simplu ([planul sursă, §1 și etapa 0](2026-09-23-scene2d-simple-collections-and-internal-spatial.md)).

**Autoritate nouă la 2026-09-24:** utilizatorul a delegat explicit agentului alegerea blocajelor de design/API/arhitectură și a rupturilor necesare, urmând să revizuiască rezultatul ulterior. Alegerile de mai jos sunt **ale agentului în baza acestei delegări**, nu semnături aprobate individual de utilizator și nu waiver pentru teste/platforme. Planul istoric consemnează corect că ele lipseau înainte; prezentul document îi adaugă un record de decizie ulterior, fără a rescrie retroactiv acea stare. Inventarul, matricea și contractul au fost acceptate la auditul independent al artefactelor; checkpoint-ul checklist este supus re-auditului înainte de etapa 1.

**Observat, nu propus:** `SceneItems2D.ItemsSource` este acum `ISceneSpatialSource2D<object>?`, identitatea realizărilor este `Entry.Id`/`Version`, `Refresh()` reîncearcă pregătirea spațială, iar template-ul primește `Index = -1` (`UI/Controls/SceneItems2D.cs:12-66,204-268,439-451`). `TileMap2D.Source` expune `TileMapSource2D`, inclusiv în proprietatea UI; `TileMap2D.FromModel` este modificarea existentă a utilizatorului și trebuie păstrată (`UI/Controls/TileMap2D.cs:15-16,37-44`). `Scene2DPackageLevel` expune atât surse, cât și lease-uri pentru metadate, entități și promovări (`Cerneala.Scene2D.Packages/Scene2DPackageLevel.cs:28-97`).

**Tradeoff decis sub delegare:** un transport public de octeți păstrează streaming-ul pachetelor în formatul CPV2 cunoscut framework-ului fără metadate spațiale publice. Nu descrie formatul arbitrar al aplicației, envelope-urile spațiale custom, selecția dinainte de materializare sau rescrierea catalogului/chunk-ului. Alegem limitările explicite din §7 în locul reintroducerii aceleiași familii spațiale sub alt nume. Ele sunt rupturi de capabilitate asumate în record, nu prezentate drept păstrare echivalentă.

## 2. `SceneItems2D`: contractul selectat pentru colecții obișnuite

### Suprafața publică selectată

```csharp
public IEnumerable? ItemsSource { get; set; }
public void Refresh();
public int RealizedItemCount { get; }
```

`ItemsSourceProperty` devine proprietatea UI corespunzătoare lui `IEnumerable?`. Nu se păstrează un overload/alias care acceptă `ISceneSpatialSource2D<object>`. Se elimină `TryGetRealizedNode(string, ...)`, `Preparation` și `PreparationError`: primul pretinde un ID care nu există într-o colecție obișnuită, iar ultimele două descriu I/O asincron de care controlul simplu nu mai este proprietar. `RealizedItemCount` devine numărul nodurilor logice efectiv deținute în `LogicalChildren` de această instanță, inclusiv dacă un callback a întrerupt atașarea completă; nu este numărul intrărilor din viewport și nu promite culling înainte de realizare. Acestea sunt rupturi publice selectate sub autoritatea delegată, încă neimplementate. Contractul actual al membrilor este vizibil în `UI/Controls/SceneItems2D.cs:35-66,117,147-202` și `docs-site/documentation/classes/Cerneala.UI.Controls.SceneItems2D.md:85-120`.

### Enumerare, notificări și identitate

1. Sursa este o secvență ordonată de *ocurențe*, nu un set de obiecte distincte. La asignare se enumeră o singură dată într-un snapshot ordonat, inclusiv când controlul este detașat. Nu se enumeră la fiecare frame. Un `IEnumerable` fără notificări își păstrează snapshot-ul la detach/reattach; numai `Refresh()` sau rebind îl re-enumeră. Prima asignare poate consuma un enumerator one-shot; un `Refresh()` sau rebind ulterior necesită ca sursa să suporte o nouă enumerare, altfel eșecul de preflight păstrează arborele comis. Mutațiile tăcute nu apar automat. `ItemsControl` fotografiază sursa la asignare și pe evenimente, însă re-enumeră la reattach; acesta este un precedent, nu dovada că aceeași regulă servește `SceneItems2D` (`UI/Controls/ItemsControl.cs:426-519`; `tests/Cerneala.Tests/Controls/ItemsControlTests.cs:57-71`).
2. Pentru `INotifyCollectionChanged`, un singur abonament este activ cât timp există contextul de scenă. La atașare, sursa observabilă se re-enumeră pentru a recupera modificările făcute cât controlul era detașat. După fiecare `Add`, `Remove`, `Move`, `Replace` sau `Reset`, controlul enumeră starea *post-eveniment* o singură dată. Datele evenimentului stabilesc corespondența ocurențelor pentru delte valide; snapshot-ul final o verifică. Un eveniment cu indici/range-uri inconsistente nu este aplicat orbește: se tratează ca `Reset` sau se respinge cu eroare explicită, fără publicare parțială. Alegerea exactă a fallback-ului propusă aici este `Reset` complet, pentru a afișa totuși starea reală a sursei.
3. Fiecare ocurență primește un token intern distinct. Pentru delte observabile valide, `Add` creează tokenuri noi, `Remove` retrage doar tokenurile eliminate, `Move` mută tokenurile, iar `Replace` le înlocuiește numai pe cele afectate. Astfel, nodurile neafectate rămân aceleași chiar când aceeași referință de model apare de două ori. `Reset`, `Refresh()`, o sursă nouă și schimbarea template-ului sunt granițe de identitate: toate realizările acelei instanțe se refac. Nu se folosește `Equals` sau indexul ca ID public. Actuala păstrare a identității prin ID/Version și testul de reordonare sunt în `UI/Controls/SceneItems2D.cs:204-268` și `tests/Cerneala.Tests/Controls/SceneItems2DIncrementalContractTests.cs:44-60`.
4. `null` este o ocurență reală, nu este eliminat în tăcere. Este valid numai dacă un template care acceptă `null` produce un `SceneNode2D` distinct; altfel controlul aruncă `InvalidOperationException` ca eroare de template explicită, nu `NullReferenceException`. Implementarea de bază `ContentTemplate.CanApply` potrivește `null` numai prin `DataType == null`; metoda este virtuală (`UI/Controls/Templates/ContentTemplate.cs:42-57`). Același obiect-model poate apărea de mai multe ori, dar același obiect `SceneNode2D` nu poate fi inserat de două ori în arbore; dacă un template îl returnează de două ori, operația eșuează. Validările produse de control — niciun template aplicabil, rezultat al template-ului nul sau de tip greșit în loc de `SceneNode2D`, ori același `SceneNode2D` returnat pentru mai multe ocurențe/deja atașat altui proprietar — aruncă `InvalidOperationException`; mesajul exact nu este contractual. Calea spațială actuală interzice payload-ul null și verifică nodurile duplicate (`UI/Controls/SceneSpatialSource2D.cs:61-68`; `UI/Controls/SceneItems2D.cs:210-232`).
5. Template-ul primește modelul ocurenței drept `DataContext`; `ContentTemplateContext.Index` rămâne `-1`. Acesta este contractul actual `SceneItems2D` și evită promisiunea falsă că un context cu index readonly se actualizează după `Move` (`UI/Controls/SceneItems2D.cs:439-451`; `UI/Controls/Templates/ContentTemplateContext.cs:7-31`). Nu se adoptă implicit indexul zero-based al `ItemsControl`.
6. Asignarea, `Refresh()` și notificările unei surse observabile **atașate** se execută pe firul proprietar UI. Aplicația mută colecția prin `UiRelay` când pornește de pe alt fir; controlul nu postează un eveniment produs după ce o colecție arbitrară s-a modificat deja în alt fir. `ItemsControl` respinge explicit notificările off-owner (`UI/Controls/ItemsControl.cs:486-529`). Calea veche `SceneItems2D` putea posta publicații ale unui catalog imutabil, contract diferit (`UI/Controls/SceneItems2D.cs:469-491`). Înainte de prima atașare, asignarea/snapshot-ul rulează pe firul constructorului/apelantului; nu se creează noduri de template până când există owner de scenă. După prima atașare, accesul respectă owner-ul chiar dacă instanța este momentan detașată.
7. `Refresh()` este o **re-enumerare explicită, sincronă și de tip Reset** pe firul owner, nu o reîncercare de I/O. Dacă re-enumerarea sau fabrica template-ului eșuează **înainte de mutația structurală**, excepția ajunge la apelant și arborele comis anterior rămâne; următoarea notificare, `Refresh()` sau rebind poate reîncerca. Excepțiile aruncate chiar de o fabrică template furnizată de aplicație se propagă nemodificate; regula `InvalidOperationException` de mai sus se aplică numai validărilor controlului. Pentru `ObservableCollection`, excepția poate ajunge la mutator chiar dacă sursa s-a schimbat deja. Nu există un nou `PreparationError` cu semnificație inventată. După un eșec **în faza structurală**, controlul intră în fault terminal conform paragrafului următor și `Refresh()` nu mai promite recovery.

### Publicare tranzacțională și lifecycle

Se pregătesc snapshot-ul și toate nodurile candidate înainte de schimbarea `LogicalChildren`; numai după verificarea sursei, generației și contextului încă active începe mutația. O re-intrare în timpul enumerării/fabricii invalidează candidatul vechi; acesta se curăță fără publicare târzie. Dacă enumerarea/fabrica eșuează **în preflight**, nodurile comise și resursele lor rămân; candidații neatașați se retrag. Aceasta nu promite rollback al efectelor arbitrare din codul fabricii. Actualul `SceneItems2D` pregătește candidații înainte de mutații structurale și are un test de eșec al fabricii, dar commit-ul secvențial nu este un rollback global (`UI/Controls/SceneItems2D.cs:204-268`; `tests/Cerneala.Tests/Controls/SceneItems2DIncrementalContractTests.cs:405-425`).

`ItemsSource` ca proprietate UI poate fi deja nouă când callback-ul său aruncă. **Nu pretindem rollback-ul proprietății.** După un eșec de preflight, controlul păstrează nodurile vechi, marchează snapshot-ul cerut necomis, dezabonează sursa veche și abonează sursa nouă numai când contextul este activ; următoarea notificare/`Refresh()`/reattach poate reîncerca. O pregătire de coliziune nu declară noua sursă ready și propagă eroarea reală, nu un `EntryId` sintetic.

După **începerea mutației structurale**, un callback de attach/detach/`Changed` poate arunca *după* schimbarea parentului/membership-ului (`UI/Elements/UIElementCollection.cs:39-53,155-183`). `UIElement.AttachToRoot` și `SceneNode2D.AttachSimulationContext` pot seta starea înainte de callback și nu oferă replay sigur după excepție (`UI/Elements/UIElement.cs:668-714`; `UI/Elements/ElementLifecycle.cs:5-24,58-103`; `UI/Controls/SceneNode2D.cs:69-104`). **Nu garantăm rollback sau recovery prin `Refresh()` pentru asemenea erori.** Orice eșec al fazei structurale pune această instanță `SceneItems2D` în stare terminală de fault: eroarea reală este propagată, pregătirea de coliziune eșuează explicit, iar încercările viitoare de `Refresh()`/rebind nu publică noduri noi și raportează că instanța trebuie înlocuită. Owner-ul local dezabonează sursa observabilă, inspectează `LogicalChildren` după excepție și aliniază tokenurile/`RealizedItemCount` cu membership-ul observabil, încearcă cleanup pentru candidații nepublicați și toate resursele retrase și agregă erorile fără să ascundă cauza primară. Nu pretinde că poate repara efectele parțiale ale hook-urilor externe. Schimbările de sursă/template re-intrante se amână până iese mutația curentă; dacă generația s-a schimbat, commit-ul exterior se oprește, iar în fault terminal nici ultima generație nu este publicată. Caller-ul tratează excepția și înlocuiește controlul, fără afirmația că eliminarea lui repară automat orice efect extern. Teste RED deterministe trebuie să arunce din attach, detach și `Changed`, să verifice numărul/membership-ul local, propagarea/aggregarea erorilor, lipsa readiness fals pozitiv și absența publicării unei generații vechi. Acest contract îngust nu extinde `UIElementCollection` sau lifecycle-ul comun.

Detach/context replacement normal retrage abonamentul, anulează lucrul controlului, scoate nodurile din arborele scenei și păstrează doar snapshot-ul simplu necesar reattach-ului. Lifecycle-ul normal al imaginilor, inputului și colliderelor rămâne la `SceneNode2D`/scenă, nu se mută în model (`UI/Controls/SceneNode2D.cs:69-168,202-229`; `UI/Controls/SceneItems2D.cs:461-527`).

## 3. Pachete și încărcare proprie: transport simplu, format cunoscut

### Formatul și ownerii actuali

Pachetul are `catalog.c2d`, `payloads.c2d` și `assets`. `OpenAsync(directory)` verifică catalogul și checksum-ul, decodifică indexul CPV2, apoi citește blocuri dintr-un `SafeFileHandle` prin `RandomAccess`; indexul conține cataloagele spațiale și offset/length/hash pentru fiecare payload (`Cerneala.Scene2D.Packages/PackageFiles.cs:3-8,31-59`; `Cerneala.Scene2D.Packages/Scene2DPackage.cs:35-64,88-120`; `Cerneala.Scene2D.Packages/PackageIndex.cs:6-18`). `PackageValueCodec` nu este un decoder arbitrar al formatului aplicației (`Cerneala.Scene2D.Packages/PackageValueCodec.cs:11-18,31-59`). Scriitorul pornește de la `Scene2DDocument` deja materializat și produce un director local; importerele Tiled/LDtk primesc căi locale (`Cerneala.Scene2D.Packages/Scene2DPackageWriter.cs:10-44,54-77`; `Cerneala.Scene2D.Importers/TiledScene2DImporter.cs:13-26`; `Cerneala.Scene2D.Importers/LdtkScene2DImporter.cs:11-24`).

### API public selectat **nou**, numai pentru transportul CPV2 pregătit

```csharp
public enum Scene2DPackagePart { Catalog, Payloads }

public interface IScene2DPackageRangeReader : IAsyncDisposable
{
    ValueTask<long> GetLengthAsync(
        Scene2DPackagePart part, CancellationToken cancellationToken = default);
    ValueTask<int> ReadAsync(
        Scene2DPackagePart part, long offset, Memory<byte> destination,
        CancellationToken cancellationToken = default);
}

public static Task<Scene2DPackage> OpenAsync(
    IScene2DPackageRangeReader reader,
    Scene2DPackageReadOptions? options = null,
    CancellationToken cancellationToken = default);
```

Overload-ul existent `OpenAsync(string directory, ...)` rămâne și folosește un adaptor intern pentru fișiere locale. Aplicația poate implementa reader-ul prin fișiere proprii, range-uri HTTP sau un depozit cu chei opace; API-ul îi cere doar octeți la offset, **nu** bounds, tile IDs, chunk IDs, catalog, `IsSimulated` sau lease-uri. Datele servite trebuie totuși să fie un pachet CPV2 pregătit. Dacă aplicația are un format propriu, îl transformă într-un `Scene2DDocument`/pachet prin calea de import/compilare ori își decodifică propriile modele și folosește `TileMap2D.FromModel`/colecții simple. Nu promitem un importer de server sau un writer remote care nu există.

Reader-ul reprezintă o **revizie imuabilă** a aceluiași pachet pe toată durata lui: lungimile raportate pentru catalog/payload rămân stabile și offset-urile citesc aceiași octeți. Apelurile `ReadAsync` pentru offset-uri independente pot fi concurente. Un rezultat valid este între `0` și `destination.Length`; citirile scurte sunt permise, iar `0` înainte de final este trunchiere. Reader-ul nu reține și nu atinge `destination` după completarea operației returnate. Pachetul verifică offset/lungime/buget/hash/tip și propagă anularea per apel, fără retry automat nou. Un adaptor peste un singur `Stream` cu `Seek` serializează poziționarea+citirea sau folosește stream-uri/range-uri independente. Acest contract de transport nu mută selecția chunk-urilor în aplicație (`Cerneala.Scene2D.Packages/Scene2DPackage.cs:88-120`).

Ownership-ul reader-ului ne-null trece **o singură dată la intrarea în `OpenAsync`**, chiar dacă opțiunile sunt invalide ori tokenul este deja anulat. La eșecul deschiderii, `DisposeAsync` al reader-ului este așteptat; dacă atât deschiderea, cât și cleanup-ul eșuează, ambele erori sunt păstrate într-un agregat, fără pierderea cauzei primare. La succes, `Scene2DPackage` implementează `IDisposable` și **nou** `IAsyncDisposable`. `Dispose()` respinge imediat cereri noi și pornește drain-ul citirilor admise; nu declară că toate s-au terminat. `DisposeAsync()` poate fi apelat înainte sau după `Dispose()` și întoarce aceeași completare terminală pentru apeluri repetate: așteaptă toate citirile admise, închide reader-ul o singură dată și propagă erorile de cleanup agregate. Caller-ul care folosește numai `Dispose()` nu are dovada unei închideri fără erori târzii; trebuie să aștepte `DisposeAsync()` pentru acea dovadă. Overload-ul local cu `SafeFileHandle` păstrează comportamentul existent de respingere a citirilor noi și terminare a celor deja admise (`Cerneala.Scene2D.Packages/Scene2DPackage.cs:78-120`). Fake-reader tests trebuie să acopere revizie/lungimi instabile, count invalid, folosire târzie a bufferului, citiri scurte/zero, concurență, anulare, hash invalid, opțiuni invalide, cleanup eșuat și Dispose/DisposeAsync intercalate.

`GetFilePath(relativePath)` rămâne numai pentru pachetele deschise din director local. El promite o cale absolută de fișier local pentru un fișier declarat, inclusiv fișiere de referință care nu sunt imagini, și este folosit astfel de Playground (`Cerneala.Scene2D.Packages/Scene2DPackage.cs:70-76`; `Playground/Cerneala.Playground/SceneWorldPackage.cs:28`). Pentru un reader remote, această metodă aruncă `NotSupportedException` pentru o cale declarată, în loc să inventeze un fișier local. Aplicația furnizează separat imaginile prin `IResourceProvider` și `IAsyncImageLoader`, care acceptă ID-uri de resurse și încărcare asincronă după șir/cancellation token (`UI/Resources/IResourceProvider.cs:3-12`; `UI/Resources/IAsyncImageLoader.cs:5-9`; `UI/Resources/ImageResourceCache.cs:218-265`). Aceste seam-uri nu fac package reader-ul automat image-stream-aware. Integrarea automată a asset-urilor remote în reader-ul pachetului **nu** este selectată; ar cere un API/lifecycle separat. Paginile API trebuie să spună clar această limită.

### Suprafața package/map după eliminarea tipurilor spațiale publice

```csharp
public IReadOnlyList<string> TileMapIds { get; } // pe Scene2DPackageLevel
public TileMap2D CreateTileMap(string mapId);     // pe Scene2DPackageLevel

// Pe Scene2DPackage și Scene2DPackageLevel, după owner:
public ValueTask<Scene2DPackageMetadata> LoadMetadataAsync(
    CancellationToken cancellationToken = default);
// Pe Scene2DPackageLevel:
public ValueTask<Scene2DPackageMetadata> LoadMapMetadataAsync(
    string mapId, CancellationToken cancellationToken = default);
public ValueTask<TileMap2DModel> LoadMapModelAsync(
    string mapId, CancellationToken cancellationToken = default); // nou, model complet
public ValueTask<Scene2DEntity> LoadEntityAsync(
    string id, CancellationToken cancellationToken = default);
public ValueTask<TilePromotion2D> LoadPromotionAsync(
    TileCellKey2D cell, CancellationToken cancellationToken = default);
```

`Scene2DPackage.LoadMetadataAsync` și `Scene2DPackageLevel.LoadMetadataAsync` întorc direct `Scene2DPackageMetadata`; `LoadMapMetadataAsync`, `LoadEntityAsync` și `LoadPromotionAsync` întorc valorile indicate, nu `SceneSpatialLease2D<T>` (`Cerneala.Scene2D.Packages/Scene2DPackage.cs:67-68`; `Cerneala.Scene2D.Packages/Scene2DPackageLevel.cs:37-82`). Lease-urile actuale ale citirilor directe nu au callback de eliberare, deci valorile rămân la caller; aceasta schimbă totuși garda `.Value` după dispose-ul lease-ului și este o ruptură de API. `LoadMapModelAsync` este **nou**: încarcă toate chunk-urile unei hărți, verifică fiecare bloc și reconstruiește un `TileMap2DModel` complet pentru editare în aplicație; nu este calea de randare progresivă. Costul de I/O/memorie este proporțional cu harta întreagă și nu se ascunde într-un getter. Citirea de sursă arată că metadata păstrează tile set-urile complete și extent/versiune/proprietăți ale chunk-urilor authored, iar catalogul păstrează configurația de prezentare; pachetele pot subdiviza chunk-urile în piese de cel mult 16×16, deci loader-ul trebuie să reasambleze celulele pe coordonate în extent-ul authored, păstrând inclusiv cele goale, și să respingă holes/duplicate/out-of-range înainte de constructorul public `TileMap2DModel` (`Cerneala.Scene2D.Packages/Scene2DPackageWriter.cs:54-77,144-174`; `Cerneala.Scene2D.Packages/Scene2DPackageMetadata.cs:17-19`; `UI/Controls/TileMap2DModel.cs:327-397`). Pentru free-placement, concatenează grupurile `placements:{start}` în ordinea sursei (`UI/Controls/TileMapSource2D.cs:140-175`). Nu există în sursa inspectată o lipsă de câmp necesar; totuși Stage 1 trebuie să confirme prin roundtrip RED→GREEN, nu să trateze analiza statică drept test. `TileMaps : IReadOnlyList<TileMapSource2D>` și `CreateEntitySource(...)` dispar din API-ul public, cu migrările și pierderile enumerate în §7. `TileMap2D.Source`/`SourceProperty` nu pot rămâne publice cu tipul eliminat. `TileMap2D.FromModel(model, imageSizes?)` și compunerea directă de scene rămân.

`CreateTileMap` creează un nod nou per apel, cu rezidență și warm cache **per instanță**, însă folosește privat indexul/chunk-urile pachetului; nu reconstruiește map-ul eager din `TileMapIds`. ID-ul de mapă este unic numai în nivel, deci identitatea inter-nivel este `(level.Id, mapId)` (`Cerneala.Scene2D.Packages/Scene2DPackage.cs:152-157`). Header-ele interne păstrează bounds și count de colidere înainte de load, tile/image IDs, dimensiuni naturale declarate, `DataResidencyBytes` nullable (necunoscut, nu zero), versiunile/reviziile de chunk, paletele și prezentarea `IsVisible`/`Opacity`/`Offset`/`Tint` (`UI/Controls/TileMapCatalog2D.cs:15-83,99-204`; `UI/Controls/TileMapSource2D.cs:140-219`; `UI/Controls/TileMap2D.cs:85-89,113-159`). Validarea exactă a paletelor/reviziilor după load rămâne responsabilitatea owner-ului intern package/tile; simplul ID public nu o înlocuiește. Un pod intern între assembly-ul core și package este **planificat**, nu există încă (`Properties/AssemblyInfo.cs:3-10`; `Cerneala.Scene2D.Packages/Cerneala.Scene2D.Packages.csproj:8-11`).

`TileMap2D` deține în continuare selecția viewport/coliziune, achizițiile partajate, limita și retenția warm, anularea la detach/înlocuire, retry-ul prin `TileMap2D.Refresh()`, coliderii rezidenți și eliberarea payload-ului/imaginilor după ultimul interes (`UI/Controls/TileMap2D.Streaming.cs:37-54,68-207,415-488`; `UI/Controls/TileMap2D.WarmCache.cs:9,98-128,340-454`). Reader-ul de octeți nu decide acestea. Pachetul deține numai transportul și validarea blocurilor. Caller-ul deține `Scene2DPackage` și ține pachetul nedisposed cât o hartă creată poate cere chunk-uri; `Scene2DPackage.Dispose()` nu distruge nodurile returnate, dar respinge citiri viitoare, iar citirile deja începute se pot termina. Harta nu primește ownership asupra handle-ului pachetului. Formatul CPV2 și bitul `IsSimulated` deja serializat nu își schimbă bytes/versiunea; fixture-urile scrise anterior trebuie să rămână lizibile, nu doar pachetele generate după cutover.

**Lacună observată în cleanup-ul actual:** `TileMap2D.StopSource` apelează `SceneSpatialResidency2D.Dispose()` sincron, nu `DisposeAsync`; publicul `Preparation` este task-ul încărcărilor curent cerute, nu o dovadă că loader-ele întârziate și eliberările lor s-au terminat (`UI/Controls/TileMap2D.Streaming.cs:26-27,174-207,447-488`; `UI/Controls/SceneSpatialResidency2D.cs:128-146,231-243,245-305`). Așteptarea lui `Preparation` înainte de `Scene2DPackage.Dispose()` nu ar demonstra quiescence. Selectăm `TileMap2D : IAsyncDisposable` cu `ValueTask DisposeAsync()` terminal. Instanța înregistrează **înaintea încercării de cleanup** fiecare generație curentă/retrasă prin detach, reattach sau rebind, apoi păstrează task-ul de drain al acelei generații chiar dacă operația sincronă aruncă sau câmpul activ devine null. Dacă cleanup-ul sincron al unei generații aruncă, eroarea este păstrată, celelalte generații tot se retrag, iar drain-ul continuă. `DisposeAsync()` agregă erorile sincrone și asincrone de release din toate generațiile, așteaptă toate operațiile deja pornite și, la repetare, întoarce aceeași completare terminală, inclusiv același rezultat faulted. Apelul trebuie făcut după detach, pe firul owner al ultimei atașări sau, pentru o hartă niciodată atașată, pe firul creatorului; apelul pe un map încă atașat aruncă `InvalidOperationException` fără a consuma starea terminală, astfel caller-ul poate detașa și apoi apela valid `DisposeAsync()`. După un apel valid, reatașarea hărții aruncă `ObjectDisposedException`. Mesajele exacte ale acestor erori nu sunt contractuale. Caller-ul așteaptă terminalul înainte de `Scene2DPackage.DisposeAsync()` dacă cere shutdown complet. În `StopSource`, map owner-ul capturează și stochează **numai propriile erori** de residency/source release/dispose pe completarea de retirement deja urmărită, în loc să le arunce prin detach-ul arborelui. Astfel, detach-ul obișnuit se încheie structural chiar dacă release-ul intern aruncă, rămâne reutilizabil și nu promite așteptare sincronă; erorile sincrone și cele tardive din toate generațiile se livrează la terminalul `DisposeAsync()`. Nu se interceptează aici excepțiile unor hook-uri lifecycle arbitrare ale aplicației și nu se promite rollback pentru ele. Testul obligatoriu este detach → reattach → completare întârziată a generației vechi → detach → `DisposeAsync`, inclusiv erori din ambele generații. Această suprafață este **selectată, nu existentă** în sursa actuală.

## 4. Coliziune, readiness și diagnostic

`SceneItems2D` simplu materializează sincron nodurile scenei; colliderii lor intră în lumea de coliziune existentă. Pentru un snapshot comis nu există intrare de colecție „neîncărcată” și nu se fabrică `EntryId` din index/model/nod. Dacă publicarea noului snapshot a eșuat, pregătirea regiunii propagă eșecul real și nu declară noua stare ready. Streamer-ul intern tile/package continuă să raporteze payload-uri lipsă prin ID-ul real local sursei/chunk-ului; `SceneCollisionRegionNotReadyException.EntryId` își păstrează sensul actual: prima intrare lipsă, locală sursei, nu ID global și nu lista completă (`UI/Controls/CollisionWorld2D.Streaming.cs:15-63,99-138,229-242`; `docs-site/documentation/classes/Cerneala.UI.Controls.SceneCollisionRegionNotReadyException.md:19,36`).

**Marker selectat, încă neimplementat:** `Collider2D.IsSimulated : bool`, implicit `false`, înseamnă numai „acest collider deja materializat cere păstrarea datelor de coliziune în apropierea propriei geometrii active”. Nu pornește simulare fizică și nu garantează că un alt collider poate forma o pereche de contact cu el. Nu se moștenește de către descendenți, grupuri sau celelalte collidere ale unui actor; fiecare collider dorit se marchează separat. `TileStaticCollider2D` generat de framework rămâne nemarcat, astfel nu își fixează singur propriul teren (`UI/Controls/TileStaticCollider2D.cs:6-40`; `UI/Controls/TileMap2D.Collision.cs:57-71,118-124`). Pentru `IsSimulated = true`, interesul folosește doar geometria proprie pentru care `TryGetActiveSceneGeometry` reușește: `Collider2D.Enabled`, `CollisionLayer != 0` și vizibilitate efectivă; trigger-ul și `CollisionMask == 0` **nu** o exclud din interesul geometric (`UI/Controls/Collider2D.cs:106-120`). `Enabled = false` suprimă interesul; `UIElement.IsEnabled = false` singur **nu** îl suprimă, deoarece nu este una dintre condițiile acestei metode. Contractul păstrează eligibilitatea geometrică existentă, nu inventează o condiție de input/UI. RED-ul din etapa 1 trebuie să distingă explicit cele două proprietăți, inclusiv un collider marcat cu `IsEnabled = false` și `Enabled = true`. Aplicația decide explicit ce collidere actor marchează. Valorile încărcate direct din package nu sunt marcate automat.

Mutarea, filtrarea, schimbarea formei/vizibilității, înlocuirea colliderului sau modificarea markerului invalidează interesul. Alegem inițial revizia existentă `Scene2D.CollisionMutationVersion`, nu un al doilea sistem speculativ de versiuni: schimbarea markerului publică mutația prin owner-thread, iar `CollisionWorld2D` verifică această revizie la refresh și reconstruiește interesele marcate din geometria curentă. Cache-ul actual verifică numai catalogul, transform/visibility participant și versiunea regiunii explicite; nu urmărește astăzi mutațiile colliderelor (`UI/Controls/Scene2D.cs:56-75`; `UI/Controls/Collider2D.cs:136-183`; `UI/Controls/CollisionWorld2D.Streaming.cs:99-138,184-185`). Reconcilierea collision-index la marker change poate fi un no-op funcțional, dar costul reviziei globale nu este măsurat. Testele idle/mutație și scena cu actor marcat care se îndepărtează de teren trebuie să demonstreze invalidare la schimbări reale, fără pinning perpetuu după plecare.

Limita este explicită: actualul `SceneSpatialEntry2D.IsSimulated` + `CollisionBounds` poate fixa teren înainte de materializarea actorului; un marker de collider apare prea târziu pentru un actor care nu a fost încă încărcat (`UI/Controls/SceneSpatialSource2D.cs:8-35`; `tests/Cerneala.Tests/Controls/SceneCollisionStreamingTests.cs:181-220`). Pentru colecția eager aleasă, actorii există înainte de interesul de coliziune; pentru entități lazy încă lipsă, aplicația folosește `SceneCollisionRegion2D` explicit și îi actualizează regiunea prin release/reacquire când actorul se mișcă (`UI/Controls/CollisionWorld2D.Streaming.cs:15-63,188-227`). Aceasta este o reducere **asumată** a bootstrap-ului auto off-camera al unui provider arbitrar. `SceneNode2D`, `Sprite2D`, `Collider2D` și rolurile package nu au azi markerul selectat; `Layer`/`SimulationContext`/rolul `Collider` nu sunt clasificatori de actor (`UI/Controls/SceneNode2D.cs:29,116-153`; `UI/Controls/Sprite2D.cs:12-33`; `UI/Controls/Collider2D.cs:61-95`; `Cerneala.Scene2D.Packages/Scene2DPackageEntityInfo.cs:9-32`). Formatul CPV2 serializează încă bitul vechi `SceneSpatialEntry2D.IsSimulated`; îl păstrăm în wire/indexul privat fără schimbare de bytes sau versiune, iar fixture-uri package existente trebuie să rămână lizibile (`Cerneala.Scene2D.Packages/PackageValueCodec.cs:228-231,368-371`).

## 7. Diferențe față de capabilitatea actuală: rupturi selectate sub delegare

1. **Storage custom ≠ format/streaming arbitrar.** Reader-ul de range-uri permite fișiere/servere proprii care servesc CPV2 pregătit. Nu permite framework-ului să descopere bounds/chunks din formatul propriu al aplicației. Pentru un format arbitrar, aplicația decodifică un model complet și îl furnizează lui `FromModel`/`SceneItems2D`; nu primește culling/chunk residency automat. Un contract public de metadate spațiale + acquire/release ar readuce familia interzisă. Selectăm această limită și o documentăm drept ruptură, nu ca suport echivalent.
2. **`CreateEntitySource` nu are substitut semantic complet în reader.** Astăzi callback-ul aplicației alege envelope vizual/de coliziune, `IsSimulated`, includere/ordine, iar sursa poate publica modificări (`Cerneala.Scene2D.Packages/Scene2DPackageLevel.cs:55-74`; `docs-site/documentation/classes/Cerneala.Scene2D.Packages.Scene2DPackageLevel.md:75-98`). Alegem valori directe după ID și `SceneItems2D` simplu: aplicația selectează header-ele, încarcă entitățile dorite, le inserează în colecția ei și marchează explicit colliderii realizați care cer pinning. Se pierde selecția/rezidența automată *dinainte de load* după envelope custom; pentru zona încă neîncărcată aplicația folosește `SceneCollisionRegion2D` explicit. Un presenter package-only cu header-ele authoring nu ar păstra callback-ul custom și ar impune o politică nouă; nu îl construim preventiv.
3. **Editarea `CellPublication` migrează la model complet, cu cost diferit.** Playground înlocuiește acum un singur `TileCell2D` într-un chunk grid fără colidere, incrementează reviziile catalog/chunk și folosește metadatele pentru a construi datele editate (`Playground/Cerneala.Playground/SceneWorldPackage.cs:73-188`; `UI/Controls/TileMap2DModel.cs:21-46,90-109,208-290`). Alegem `LoadMapModelAsync(mapId)` pentru o copie completă la primul edit, reconstrucția în aplicație a chunk-ului/modelului imutabil după schimbarea unei celule, apoi `TileMap2D.FromModel(model, imageSizes)` și înlocuirea nodului de hartă pe owner-thread. `imageSizes` se construiește din `Scene2DPackage.Assets` (`Scene2DAsset.ResourceId`/`Size`), nu din modelul care nu conține aceste dimensiuni; fără ele, free-placement natural-size poate eșua (`Cerneala.Scene2D.Packages/Scene2DPackage.cs:31`; `UI/Controls/Scene2DDocument.cs:8-34`; `UI/Controls/TileMapSource2D.cs:155-163`). `TileCellKey2D`, `TileCell2D`, `TileChunk2D` și `TileMap2DModel` au date/read APIs și constructori de snapshot, nu un setter de celulă (`UI/Controls/TileMap2DModel.cs:21-46,90-109,208-290,327-442`). Funcția vizibilă de plant/promote rămâne de testat, dar identitatea nodului, chunk-cache-ul și costul devin **altele**: prima editare încarcă harta completă, fiecare publicare reconstruiește date/noduri relevante și poate pierde warm residency. Nu pretindem echivalență cu `CellPublication` incremental. Dacă roundtrip-ul pierde paleta, coliderii sau dimensiunile de imagine, implementarea se oprește înainte de producție; analiza sursei nu înlocuiește testul. Nu adăugăm un nou API public de tranzacție/catalog în acest scope.
4. **Pinning-ul pre-load al entităților lazy custom nu este identic cu markerul de collider.** Markerul ales funcționează numai pentru actorii deja realizați din colecție; `IsSimulated`/`CollisionBounds` vechi funcționau înainte de realizare. Alegem regiuni explicite gestionate de aplicație pentru actorii încă neîncărcați. Mutarea regiunii rămâne în sarcina aplicației. Acesta este un contract mai îngust, nu echivalență ascunsă.
5. **Asset-urile remote nu au `GetFilePath`.** Ruta aleasă este provider/loader-ul de imagini existent, configurat de aplicație. Pachetul remote nu furnizează stream-ul imaginii prin reader-ul CPV2; un astfel de serviciu ar avea un lifecycle public separat și este în afara acestui scope.

Contractul selectat păstrează streaming-ul mapelor CPV2 *framework-owned* și încărcarea de valori după ID, cu transport app-owned ne-spațial; nu adaugă o familie publică de catalog/entry/lease sub alt nume. Cele cinci diferențe sunt decizii de compatibilitate/produs asumate de agent sub delegarea utilizatorului. Implementarea nu are voie să le camufleze prin shim-uri sau să afirme că testele vechi de streaming custom au același contract; caracterizarea lor rămâne dovadă pentru comportamentul vechi și testele noi fixează schimbarea aprobată prin această delegare.

## 9. Ledger de decizie și condiții rămase

1. **Selectat sub delegarea din 2026-09-24:** semantica `SceneItems2D` din §2, inclusiv ocurențe duplicate/null, tokenuri la delte, `Index=-1`, owner-thread, Reset/Refresh și eliminarea/redefinirea membrilor auxiliari. Preflight-ul eșuat poate fi reîncercat; excepțiile din timpul commit-ului structural produc fault terminal al controlului, nu rollback magic al arborelui UI.
2. **Selectat:** reader-ul CPV2 asincron, valorile directe în locul tuturor lease-urilor package, `CreateTileMap`, `LoadMapModelAsync` complet pentru editare, `TileMap2D.DisposeAsync` terminal și asset-uri remote prin provider/loader separat. Streaming-ul mapelor pregătite rămâne; formatul arbitrar al aplicației nu primește streaming spatial automat.
3. **Selectat ca reducere explicită:** `CreateEntitySource` custom pre-load/auto-selection dispare; aplicația încarcă valori după ID și deține colecția. `CellPublication` devine reconstrucție de model complet + înlocuire de map; lazy actor bootstrap folosește regiuni explicite. Nu se adaugă presenter sau tranzacție de catalog nouă.
4. **Selectat:** `Collider2D.IsSimulated` implicit false, interes numai din geometria activă proprie, fără moștenire; `EntryId` rămâne ID real de chunk privat, nu ID sintetic de colecție. Bitul `IsSimulated` din CPV2 rămâne serializat exact ca astăzi, chiar dacă tipul devine intern.
5. **Nu este waiver:** Windows/SDL, Linux/SDL și macOS/SDL rămân probe cerute; WindowsDX este blocat până la harness/waiver nou. Niciun test, build, native probe sau ApiCompat nu a fost rulat în această etapă de decizie.

Inventarul contextual, matricea/gate-urile înghețate și contractul au fost acceptate de auditorul independent; numai cele șase sarcini și gate-ul etapei 0 sunt bifate în planul sursă, cu re-audit al checkpoint-ului încă necesar înainte de etapa 1. Căutările textuale cu scope nu dovedesc singure absența apelanților externi. Nicio schimbare de producție, teste ori documentație API nu a fost făcută în etapa 0; delegarea de design nu anulează ordinea etapelor sau verificarea ulterioară.
